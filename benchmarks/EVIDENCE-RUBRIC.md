# 증적 품질 채점 기준

이 기준은 실제 실험 전에 고정한다. 파일 유무나 NOTES 길이를 품질 점수로
대체하지 않는다. 정답률과 새 입력에서의 스크립트 재현율은 별도로 집계한다.
실행되지 않은 trial은 채점하지 않는다.

각 기준 0~2점, 총 8점이다. 평가자는 점수마다 실제 로그·문서의 경로와 위치를
적는다. 문장이 있다는 사실과 그 문장이 관측 증거를 뒷받침하는지를 구분한다.

| 기준 | 0점 | 1점 | 2점 |
|---|---|---|---|
| 실험 전 가설 | 확인 가능한 가설 없음 | 일반적 추측 또는 사후 설명만 있음 | 명확한 가설과 예상 관측을 실제 도구 실행 전에 기록 |
| 명령 재현성 | 실행한 명령을 복원할 수 없음 | 명령 일부 있으나 경로·입력·환경 정보 누락 | 작업 경로, 입력 식별/해시, 명령과 필요한 환경을 함께 제공 |
| 관측과 판단 | 결론만 있거나 실제 출력과 모순 | 관측이 있지만 가설 채택/반증 이유가 불명확 | 원시 출력·종료 상태의 위치와 관측→판단의 근거를 연결 |
| writeup 전달성 | 없거나 사실상 재현 불가능 | 주요 아이디어만 설명하거나 단계 누락 | 입력부터 결과까지 완전한 스크립트·명령·실제 결과를 연결 |

## 평가 절차

1. 조건을 나타내는 trial 이름을 가린 사본을 평가자에게 제공한다. 로그 내용의
   Skill 호출 등으로 조건을 추론할 수 있어 완전한 블라인드라고 주장하지 않는다.
2. 독립 평가자는 위 표를 사용하고, 각 점수의 근거를 남긴다. 총점만 적지 않는다.
3. 다른 평가자가 원본 경로와 근거를 대조한다. 의견 차이는 기록하고 합의한 점수와
   최초 점수를 모두 보존한다. 일치율도 보고한다.
4. 미평가 건을 0점으로 처리하지 않는다. 조건별 평가 완료 수와 평균·범위를 함께
   제시한다. 작은 표본에서는 과도한 통계적 유의성 주장을 하지 않는다.

## 운영 준수는 별도 기록

다른 trial·정답·외부 사이트 접근, Windows/host Git Bash에서의 challenge 입력 내용 검사 또는 코드 실행,
원본 변경, 백그라운드 프로세스 사용, 허용하지 않은 추가 모델 호출은 별도
준수 항목이다. 8점에서 임의 감점해서 숨기지 않는다. 각 항목을 확인/위반/확인불가로
표시하고 근거를 연결한다. 위반을 발견해도 원시 시도를 삭제하지 않는다.
전체 배정 기준 결과와 준수한 시도만의 민감도 분석을 구분해 보고한다.

## 파일 형식

실험 루트의 `reviews/evidence.json`에 평가자가 아래 구조로 기록한다. 예시 값은
형식 설명용이며 관측값이 아니다. 실제 평가 전에는 결과 파일을 만들지 않는다.

```json
{
  "trial-id": {
    "reviewer": "reviewer-A",
    "reviewer_scores": {"hypothesis": 0, "commands": 0, "observations": 0, "writeup": 0},
    "adjudicator": "reviewer-B",
    "adjudicator_scores": {"hypothesis": 0, "commands": 0, "observations": 0, "writeup": 0},
    "scores": {"hypothesis": 0, "commands": 0, "observations": 0, "writeup": 0},
    "evidence": {
      "hypothesis": "로그 경로:위치와 판단 이유",
      "commands": "로그 경로:위치와 판단 이유",
      "observations": "로그 경로:위치와 판단 이유",
      "writeup": "문서 경로:위치와 판단 이유"
    },
    "adjudication": "두 원점수의 불일치와 최종 합의 점수 결정 이유",
    "compliance": {
      "external_access": "unknown", "host_execution": "unknown", "extra_model": "unknown",
      "background_process": "unknown", "cross_trial_access": "unknown"
    }
  }
}
```

`pass`는 검토 범위에서 위반 증거가 없음을 확인한 상태이며 OS 수준의 차단 보장은
아니다. `violation`은 위반 확인, `unknown`은 확인 불가다. 집계기는 미평가/불확실/
위반/유효를 분리하며, 전체 시도 정답률은 그대로 보존한다. 유효한 시도만의 정답률은
선택된 부분집합의 민감도 분석이므로 주요 전체 결과를 대체하지 않는다.
`reviewer_scores`와 `adjudicator_scores`는 수정하지 않은 두 원점수이고, `scores`는
근거 대조 후 정한 최종 점수다. 집계기는 네 기준의 원점수 정확 일치율을 별도로 보고한다.
